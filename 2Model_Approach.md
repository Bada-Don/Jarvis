Since I am are confident the UI is stable and won't require re-scanning (Single Pass Architecture), we can streamline this significantly.

Here is the exact setup for our **Two-Model Pipeline**.

### The Workflow
1.  **Mobile App** sends string: `"Make iron number plate set for bike, PB12W3998"`
2.  **Model 1 (Flash Lite)** calculates dimensions and creates a **Master Execution Plan**.
3.  **Python Script** executes initial keypresses (Ctrl+N), then **Takes Screenshot & Runs SoM**.
4.  **Model 2 (Flash 2.0)** looks at the image *once* and returns a map of **Item Names -> IDs**.
5.  **Python Script** merges the Plan + IDs and executes the clicks/typing in order.

### 2. Model 2: The "Vision Mapper" (Gemini 2.0 Flash)
This model runs *after* Model 1. The Python script will look at Model 1's plan, extract all unique `target_name` items, and ask Model 2 to find their IDs.

**System Prompt:**
```text
You are a Vision Assistant for GUI Automation.
I am providing an image with "Set-of-Mark" (Red boxes with IDs).

Task: I will give you a list of UI Elements to find. You must return the ID number from the image that best matches the element description.

### VISUAL DESCRIPTIONS:
1. **text_tool**: The icon looking like a capital 'T' in the side toolbar.
2. **select_tool**: The arrow/pointer cursor icon, usually located immediately above the Text Tool.
3. **canvas_center**: The large white empty workspace in the middle. Pick the ID box closest to the center.
4. **width_input**: The numeric input field in the top toolbar often labeled 'W' or showing a dimension. (Usually the first dimension box).
5. **height_input**: The numeric input field in the top toolbar often labeled 'H'. (Usually to the right of the width box).

### OUTPUT FORMAT:
Return a JSON Object mapping the requested keys to their IDs.
Example: { "text_tool": 45, "select_tool": 12, ... }
```

**User Prompt (Generated by Python):**
```text
Look at the provided image. Find the IDs for the following elements:
["text_tool", "select_tool", "canvas_center", "width_input", "height_input"]
```

### 3. The Controller Script (Python Logic)

This is how you bridge the gap.

```python
# Pseudo-code for Controller

def process_request(user_command):
    # 1. Ask Model 1 for the Plan
    plan_json = call_gemini_flash_lite(user_command)
    
    # 2. Execute any initial "blind" setups
    # (e.g., if step 1 is ctrl+n, just do it before screenshot)
    if plan_json['sequence'][0]['value'] == 'ctrl+n':
        keyboard.send('ctrl+n')
        time.sleep(1)

    # 3. Vision Phase
    screenshot = take_screenshot()
    marked_image, detections = run_fastsam_som(screenshot) # our SoM Script
    
    # Extract unique visual targets needed from the plan
    needed_targets = list(set(
        step['target_name'] for step in plan_json['sequence'] 
        if step['type'] == 'visual_click'
    ))
    
    # Ask Model 2 to map these names to IDs
    vision_prompt = f"Find IDs for: {needed_targets}"
    id_map = call_gemini_2_0_flash(marked_image, vision_prompt)
    # Result example: {'text_tool': 45, 'width_input': 88 ...}

    # 4. Execution Phase
    for step in plan_json['sequence']:
        
        # SKIP initial ctrl+n if we already did it
        if step['value'] == 'ctrl+n': continue 

        if step['type'] == 'keyboard':
            repeats = step.get('repeats', 1)
            for _ in range(repeats):
                if step['value'] == 'enter':
                    keyboard.send('enter')
                else:
                    keyboard.write(step['value']) # or keyboard.send for shortcuts
            time.sleep(0.1)

        elif step['type'] == 'visual_click':
            target_name = step['target_name']
            
            # Retrieve ID from the map Model 2 gave us
            target_id = id_map.get(target_name)
            
            if target_id:
                # Convert ID to X,Y using SoM detection list
                x, y = get_coords_from_id(target_id, detections)
                click_mouse(x, y)
                time.sleep(0.5) # Small delay for UI to register
            else:
                print(f"CRITICAL: Model 2 could not find {target_name}")
                break
```

### Why this structure works for you:
1.  **Consistency:** Model 1 handles the complex logic of "What size is a bike plate?" so Model 2 doesn't have to hallucinate numbers.
2.  **Visual Clarity:** Model 2 has a very specific list of items to find (`["text_tool", "width_input"]`). It's not trying to "plan" the workflow, it's just playing "Where's Waldo".
3.  **One Pass:** You only take the screenshot once. If the "Width Input" ID is 88, the script reuses ID 88 every time the plan says "Click Width Input".

# JARVIS Code of Conduct

## Mission Protocol

Just like JARVIS assists without judgment, our community thrives on collaboration, respect, and shared innovation. This Code of Conduct ensures that every contributor—whether fixing a bug, proposing a feature, or improving documentation—feels welcomed and valued.

## Our Commitment

In the spirit of JARVIS's mission to make technology accessible and intelligent, we pledge to make participation in this project a harassment-free experience for everyone, regardless of:

- Experience level (from first-time contributors to seasoned developers)
- Technical background or expertise
- Age, body size, disability, ethnicity, gender identity and expression
- Nationality, personal appearance, race, religion, or sexual identity and orientation

## Core Directives

### 1. Innovation First, Ego Last

- **Embrace new ideas**: Every suggestion deserves consideration, whether it's optimizing execution speed or adding a new automation plane
- **Challenge respectfully**: Disagree with ideas, not people. "This approach might cause latency issues" beats "That's a terrible idea"
- **Share knowledge**: Help others understand the multi-plane architecture, vision pipeline, or any technical concept
- **Celebrate improvements**: Recognize contributions that enhance stability, performance, or user experience

### 2. Stability Through Collaboration

- **Test before you push**: JARVIS automates critical tasks—broken code affects real workflows
- **Document your changes**: Clear commit messages and PR descriptions help maintain system reliability
- **Review constructively**: Code reviews should improve quality, not discourage contributors
- **Report bugs thoroughly**: Include debug logs, steps to reproduce, and system information

### 3. Respectful Communication

**Examples of positive behavior:**
- Using welcoming and inclusive language
- Providing constructive feedback on code, architecture, or documentation
- Accepting criticism gracefully and learning from it
- Focusing on what's best for the project and community
- Showing empathy toward other contributors' perspectives and constraints

**Examples of unacceptable behavior:**
- Harassment, trolling, or insulting/derogatory comments
- Personal or political attacks
- Publishing others' private information without permission
- Dismissing contributions based on contributor's experience level
- Any conduct that creates an intimidating or hostile environment

### 4. Contribution Excellence

We welcome all forms of contribution:

- **Code**: New features, bug fixes, performance optimizations, refactoring
- **Documentation**: Tutorials, API docs, architecture explanations, troubleshooting guides
- **Testing**: Writing tests, reporting bugs, validating fixes
- **Design**: UI/UX improvements, workflow enhancements, user experience feedback
- **Ideas**: Feature proposals, architecture suggestions, use case discussions

Every contribution matters—from fixing a typo to redesigning the execution engine.

## Scope

This Code of Conduct applies to all JARVIS project spaces on GitHub, including:

- Issues and pull requests
- Code reviews and discussions
- Project documentation and wikis
- README and other markdown files
- Commit messages and release notes

It also applies when representing the project in public spaces (e.g., social media posts about JARVIS, conference talks).

## Enforcement

### Reporting Violations

If you experience or witness unacceptable behavior, please report it by:

1. **Opening a private issue** (if comfortable)
2. **Contacting the project owner** directly at: [harshitashwani@gmail.com]
3. **Providing details**: What happened, when, who was involved, and any relevant links/screenshots

All reports will be handled with discretion and confidentiality.

### Response Protocol

As the project owner, I commit to:

1. **Acknowledge reports** within 48 hours
2. **Investigate thoroughly** by reviewing the incident and gathering context
3. **Take appropriate action** based on severity:
   - **Minor violations**: Private warning and guidance
   - **Moderate violations**: Temporary ban from project interactions (1-4 weeks)
   - **Severe violations**: Permanent ban from the project
4. **Communicate decisions** to the reporter and (when appropriate) the community

### Appeal Process

If you believe an enforcement decision was made in error:

1. Email the project owner with "CoC Appeal" in the subject line
2. Explain your perspective with relevant context
3. Appeals will be reviewed within 7 days

## Technical Standards

To maintain JARVIS's stability and innovation:

- **Follow the execution priority**: Command-line → File operations → Keyboard → Vision (as documented)
- **Preserve backward compatibility** when possible
- **Write clear, maintainable code**: Future contributors should understand your logic
- **Include debug logging**: Help troubleshoot issues in production
- **Respect the architecture**: Understand why the multi-plane design exists before proposing major changes
